# استقلال ATHR التقني — سجل القرار المعماري

**الحالة:** قيد التنفيذ — لا يُعدّ هذا المستند إعلانًا عن اكتمال تشغيل نموذج الذكاء الاصطناعي.

## الهدف

أن تكون ATHR منصة تملكها وتديرها المالكة من خلال حساباتها وصلاحياتها، وألا يكون تشغيل المساعد الذكي مرتبطًا بمزوّد ذكاء اصطناعي تجاري ثابت أو بمفتاح API تابع لشركة بعينها.

## مبادئ الملكية والتحكم

1. مستودع المصدر والنشر تحت حساب GitHub الذي تديره المالكة.
2. قاعدة البيانات والمصادقة والتخزين تحت مشروع Supabase الذي تديره المالكة.
3. نموذج الذكاء الاصطناعي يُختار من النماذج ذات الأوزان المتاحة وترخيص يسمح بالاستخدام التجاري المقصود، بعد مراجعة ترخيص النسخة المحددة.
4. تُشغّل أوزان النموذج على خادم استدلال مخصص يُدار من حساب ATHR، مع إمكانية نقل الخادم أو تبديل النموذج دون إعادة بناء الواجهة.
5. لا تُرسل رسائل المستخدمين إلى محرك الاستدلال قبل تفعيل الخادم ونشر بيانات الاستضافة والاحتفاظ والموافقة.
6. لا تُحفظ مفاتيح الاستدلال أو أسرار الخادم في ملفات GitHub أو في كود المتصفح.

## البنية المعتمدة حاليًا

- **الواجهة:** GitHub Pages.
- **الحسابات والبيانات:** Supabase Auth وPostgres.
- **طبقة المحادثة:** Supabase Edge Function باسم `athr-chat`.
- **طبقة النموذج:** نقطة استدلال يحددها مالك ATHR عبر أسرار الخادم:
  - `ATHR_INFERENCE_URL`
  - `ATHR_INFERENCE_MODEL`
  - `ATHR_INFERENCE_API_KEY` (اختياري حسب إعداد الخادم)
- **واجهة الاتصال:** صيغة طلب محادثة قياسية متوافقة مع خوادم الاستدلال الذاتية مثل vLLM. استخدام صيغة API متوافقة لا يعني الاتصال بشركة OpenAI؛ عنوان الخادم يُحدد من إعدادات ATHR السرية.

## حالة التنفيذ

- تم تحويل وظيفة `athr-chat` إلى طبقة محايدة عن المزوّد؛ لا يوجد عنوان API ثابت لمزوّد ذكاء اصطناعي تجاري داخلها.
- إذا لم تُضبط نقطة الاستدلال، تُرجع الوظيفة `engine_not_configured` ولا ترسل الرسالة إلى أي مزود.
- تم تجهيز واجهة المحادثة لاختيار العقل والموافقة الصريحة وإظهار حالة عدم جاهزية الخادم. آخر اختبار للمحادثة لم ينتج ردًا ناجحًا، لذا لا يُعلن عن تشغيل النموذج.
- قاعدة البيانات تحتوي على جدولي `conversations` و`messages`.
- سجل العقول يحتوي على سبعة عقول، وحالتها الإدارية الحالية `enabled`. هذه الحالة إدارية فقط ولا تثبت اتصال نموذج استدلال أو تشغيل كل عقل فعليًا.
- تم التحقق من وجود دور مالكة نشط للحساب الموثق. تظل صلاحيات المالك محمية من خلال التحقق الخادمي، ولا تُمنح من بيانات المتصفح.

## النموذج المرشح للاختبار

**Qwen3.5-9B** مرشح أولي للاختبار، وليس اختيارًا نهائيًا. صفحة النموذج تعرض ترخيص Apache 2.0 وتذكر توافقه مع أطر تشغيل مثل vLLM وTransformers. قبل اعتماده يجب اختبار جودة العربية المصرية، والفصحى، والإنجليزية، ودقة الإجابات، والسلامة، والسرعة، واستهلاك الذاكرة على إعداد الاستضافة المختار.

يجب حفظ نسخة الترخيص الفعلية للنموذج المعتمد داخل ملفات المشروع ومراجعة شروطها قبل الاستخدام التجاري.

## متطلبات خادم الاستدلال

- تشغيل النموذج داخل بيئة تتحكم بها ATHR من حسابها.
- HTTPS إلزامي بين Edge Function وخادم النموذج.
- مصادقة قوية للخادم، وتخزين المفتاح في أسرار Supabase فقط.
- وضع خادم الاستدلال خلف Reverse Proxy أو بوابة آمنة تسمح فقط بنقطة المحادثة المطلوبة؛ لا يُكتفى بمفتاح API وحده إذا كانت هناك نقاط تشغيل أخرى مكشوفة.
- حدود استخدام ومراقبة تكاليف، وإمكانية إيقاف الخادم فورًا.
- تحديد المنطقة الجغرافية، وسياسة السجلات، والاحتفاظ، والنسخ الاحتياطية قبل استقبال بيانات حقيقية.

## ما لم يُنفذ بعد

1. اختيار حساب استضافة الخادم وميزانيته بموافقة المالكة.
2. تشغيل النموذج واختباره فعليًا.
3. ضبط أسرار `ATHR_INFERENCE_*` في Supabase.
4. التحقق من صلاحية حساب المالكة وتفعيل دورها بأمان.
5. تفعيل العقل المركزي ثم بقية العقول بعد الاختبارات.
6. اختبار كامل من المتصفح حتى الرد والحفظ واسترجاع المحادثة.
7. اعتماد سياسة احتفاظ وحذف منشورة.

## قاعدة عدم الادعاء

نجاح GitHub Actions يعني نجاح بناء ونشر ملفات الموقع فقط. ولا يعني أن نموذج الذكاء الاصطناعي يعمل أو أن المحادثة اختُبرت. لا يُعلن عن استقلال ATHR التشغيلي قبل اختبار النموذج والخادم والواجهة وقاعدة البيانات من طرف إلى طرف.
